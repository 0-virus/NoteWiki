# 네트워크 캡슐화 — 각 계층의 전송 정보를 붙이기

상위 계층의 데이터를 하위 계층이 자신의 헤더 등으로 감싸 전달하는 과정이다. 수신 측은 해당 계층의 정보를 처리하고 상위 계층으로 데이터를 넘긴다. 이를 역캡슐화라고 한다.

왜 정보를 붙일까? 애플리케이션 본문만으로는 **어느 끝점에 전달할지, 바이트 순서를 어떻게 맞출지, 다음 장비가 누구인지** 알 수 없기 때문이다.

## 계층별 데이터 단위

| 계층 | 단위 | 주로 추가하는 정보 |
| --- | --- | --- |
| 애플리케이션 | HTTP 메시지·전용 전문 | 메서드·헤더·본문 또는 전문 필드 |
| TCP | 세그먼트 | 포트·시퀀스 번호·ACK·윈도우 등 |
| IP | 패킷 | 출발지·목적지 IP, TTL 등 |
| Ethernet | 프레임 | MAC 헤더와 오류 검사용 트레일러 등 |

```text
평문 HTTP 바이트 → TCP 세그먼트 → IP 패킷 → 링크 프레임
HTTPS 바이트 흐름: HTTP → TLS 레코드 → TCP → IP → 링크
```

이 화살표는 **계층 관계**다. HTTP 요청 하나가 항상 하나의 세그먼트·패킷·프레임에 담긴다는 뜻이 아니다. 큰 데이터는 나뉘고, 소켓 읽기 경계도 달라진다 → [[tcp-message-framing]]. TCP 제어 세그먼트에는 애플리케이션 데이터가 없을 수도 있다.

## 캡슐화와 메시지 변환의 차이

| 작업 | 바뀌는 것 | 책임 |
| --- | --- | --- |
| 전문 파싱 | 필드 바이트를 값으로 해석 | 애플리케이션 |
| DTO 매핑 | 외부 필드를 내부 데이터 모델에 대응 | 애플리케이션 |
| JSON 직렬화 | 객체를 JSON 표현으로 변환 | 앱·직렬화 라이브러리 |
| HTTP 요청 구성 | JSON을 본문으로 넣고 메서드·헤더 지정 | HTTP 클라이언트 |
| TCP/IP 캡슐화 | 전송·주소 정보를 붙여 전달 | 일반적인 소켓에서는 OS 스택 |

따라서 **전문 → JSON 변환 자체는 TCP/IP 캡슐화가 아니다.** [[protocol-gateway]]에서 변환한 결과를 새로 전송할 때 네트워크 캡슐화가 다시 일어난다. 객체 지향의 캡슐화와도 사용 맥락이 다르다.
