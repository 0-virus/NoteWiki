# 스레드 (Thread)

## 한 줄 정의

**프로세스 안에서 명령을 실제로 실행하는 하나의 작업 흐름.** 프로그램(디스크의 코드) →
프로세스(실행 중, 자원 할당받음) → 스레드(프로세스 안의 실행 단위) 순으로 구체화된다.

```
프로그램 (디스크의 실행 파일)
   ↓ 실행
프로세스 (OS가 메모리·자원 할당) — 코드, Heap, 열린 파일, 네트워크 연결, 스레드 ≥1개
   ↓ 포함
스레드 (실제 실행 흐름)
```

## 공유하는 것 vs 독립적으로 가지는 것

같은 프로세스 안의 스레드들은 대부분의 자원을 **공유**하지만, 실행 자체에 필요한
정보는 **독립적으로** 가진다. 이 구분이 [[concurrency-problem|Race Condition]]이
왜 생기는지의 출발점이다.

| 공유 (Heap) | 독립 (Stack) |
| --- | --- |
| Heap의 객체 | 각 스레드의 Stack |
| `static` 변수 | 현재 실행 위치 |
| 프로세스의 코드 | 메서드 호출 정보 |
| 파일·네트워크 연결 | 지역 변수 |

```
프로세스
├── Heap: 모든 스레드가 공유          ← 인스턴스 변수, static 변수는 여기
│   ├── 객체 A
│   └── 객체 B
├── Thread 1 Stack ← 지역 변수 독립
└── Thread 2 Stack ← 지역 변수 독립
```

→ [[servlet-lifecycle]]의 "Servlet 인스턴스 변수에 상태를 두지 마라"는 원칙이 정확히
이 그림에서 나온다. 인스턴스 변수는 Heap(공유), 지역 변수는 Stack(독립).

## 동시성 vs 병렬성

| 개념 | 의미 |
| --- | --- |
| **동시성(Concurrency)** | 여러 작업이 번갈아 실행되며 같은 시간 구간 안에서 함께 진전 (코어 1개로도 가능) |
| **병렬성(Parallelism)** | 여러 CPU 코어가 실제 같은 순간에 각각 실행 |

멀티 스레딩은 동시성을 구현하는 한 방법이고, 코어가 여러 개면 병렬 실행도 가능해진다.
**"스레드가 여러 개 = 항상 병렬"이 아니다** — 흔한 오해 지점.

## 스케줄링과 문맥 교환

OS의 스케줄러가 어떤 스레드에 CPU 시간을 줄지 결정하고, 스레드를 바꿔치기하는 것을
**문맥 교환(Context Switching)**이라 한다 — 실행 위치·레지스터·Stack 포인터를 저장하고
복원하는 비용이 든다. 그래서 **스레드가 많다고 항상 빨라지지 않는다**.

```
적절한 스레드 수 → 대기 시간 활용 → 처리량 향상
과도한 스레드 수 → 문맥 교환 증가 → 처리 속도 저하
```

## Java에서 스레드 만들기

```java
// 1. Thread 상속
public class WorkerThread extends Thread {
    @Override public void run() { ... }
}
new WorkerThread().start();

// 2. Runnable 구현 (실행할 작업과 스레드를 분리 — 더 흔히 쓰는 방식)
Thread worker = new Thread(() -> doWork());
worker.start();
```

### `start()` vs `run()`

- `start()` — JVM에 **새 스레드 생성**을 요청, 준비되면 새 스레드에서 `run()` 호출.
- `run()` — 새 스레드를 만들지 않는다. **현재 스레드**가 그냥 메서드처럼 실행한다.

비동기로 새 실행 흐름을 시작하려면 반드시 `start()`를 불러야 한다. `run()`을 잘못
호출하는 실수는 "스레드를 새로 만든 줄 알았는데 그냥 동기 실행됨" 버그로 이어진다.

## 생명주기

```
NEW → (start()) → RUNNABLE ⇄ BLOCKED / WAITING / TIMED_WAITING → TERMINATED
```

한 번 `TERMINATED`된 `Thread` 객체는 재시작할 수 없다.

## `sleep()` / `join()` / 인터럽트

- **`sleep(ms)`** — 현재 스레드를 잠재운다. CPU는 점유하지 않지만, 보유한 락은 자동
  반환하지 않는다.
- **`join()`** — 대상 스레드가 끝날 때까지 현재 스레드를 기다리게 한다. 순서를 맞출
  수 있지만, 기다리는 동안 다른 작업을 못 한다.
- **인터럽트(`interrupt()`)** — 강제 종료가 아니라 "중단 요청" 신호. 대상 코드가
  `isInterrupted()`를 스스로 확인하고 안전하게 종료해야 하는 **협력적** 취소 방식.

## CPU 중심 작업 vs I/O 중심 작업

| 작업 유형 | 예시 | 스레드 수 전략 |
| --- | --- | --- |
| **CPU 중심** | 수치 계산, 영상 처리, 압축 | 코어 수보다 늘려도 이득 제한적 |
| **I/O 중심** | DB 조회, 네트워크 통신, 파일 I/O | 대기 중 다른 스레드가 CPU 사용 가능 → 코어 수보다 많은 스레드가 유용 |

단, I/O 중심이라도 DB 연결 수·외부 서비스 한도 같은 다른 제약이 함께 걸린다 →
[[connection-pool]]의 `maximumPoolSize`가 스레드 수와 별개로 상한을 건다.

## 비동기 ≠ 멀티 스레딩

**비동기(Asynchronous)**는 "완료를 기다리지 않고 다음 흐름을 진행하는 방식"이고,
**멀티 스레딩**은 "여러 스레드를 쓰는 구현 방법"이다. 별도 스레드로 비동기를 구현할
수도 있지만, 이벤트 루프처럼 **적은 스레드(심지어 1개)로도 비동기**를 구현할 수 있다.

→ [[javascript-async]]가 바로 이 예다. JS는 **싱글 스레드**인데도 콜백/Promise/
async-await로 비동기를 구현한다 — Java의 멀티 스레드 비동기와는 "동시성을 만드는
방법"이 다를 뿐, "완료를 안 기다린다"는 비동기의 본질은 같다.

## 트랜잭션과 스레드

많은 프레임워크에서 트랜잭션 문맥은 **현재 스레드에 바인딩**된다. 새 스레드를 만든다고
기존 트랜잭션이 자동으로 이어지지 않는다 — 자세한 내용은 [[transaction]] 참고.
