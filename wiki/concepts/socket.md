# Socket — 프로그램이 OS에 통신을 요청하는 창구

소켓은 통신 끝점을 나타내는 OS 자원이자, 애플리케이션이 데이터를 보내고 받는 인터페이스다. 소켓 자체가 TCP와 같은 뜻은 아니다. TCP 스트림 소켓, UDP 데이터그램 소켓 등 서로 다른 방식이 있다.

## 왜 TCP 헤더를 코드에서 안 보나

일반적인 Java TCP 통신의 책임은 다음처럼 나뉜다.

| 담당 | 하는 일 |
| --- | --- |
| 업무 코드 | 어떤 데이터를 보내고 결과를 어떻게 처리할지 결정 |
| HTTP 클라이언트 또는 웹 서버 | HTTP 형식 생성·해석, 연결 관리 |
| JVM의 소켓 API | 연결·읽기·쓰기 요청을 OS에 전달 |
| OS TCP/IP 스택 | TCP 헤더, 시퀀스·ACK, 재전송·재조립, IP 처리 |

직접 소켓을 써도 보통 TCP 헤더는 OS가 만든다. HTTP 라이브러리를 쓰면 소켓 접근까지 감춰지므로 개발자는 URL·메서드·헤더·DTO를 주로 본다. [[servlet-container]]가 HTTP를 해석하고 [[dispatcher-servlet]]이 요청을 Controller로 연결하는 것도 같은 책임 분리다.

## 하나의 서버 포트에 여러 클라이언트가 붙는 이유

일반적인 TCP 연결은 **로컬 IP·포트 + 원격 IP·포트** 네 값으로 구분된다.

```text
192.0.2.10:51001 → 192.0.2.20:8080
192.0.2.11:51002 → 192.0.2.20:8080
```

위 주소는 설명용이다. 서버 포트가 같아도 상대 주소·포트 조합이 다르므로 별개의 연결이다. Java의 `ServerSocket`은 접속을 기다리고 `accept()`로 반환된 `Socket`은 개별 연결의 통신에 사용한다.

## 로컬 주소의 의미

- `localhost`: 보통 IPv4 `127.0.0.1` 또는 IPv6 `::1`로 해석되는 자기 자신. 외부 NIC를 거치지 않는 루프백 통신이다.
- `0.0.0.0`으로 **서버 바인딩**: 모든 로컬 IPv4 주소에서 받겠다는 의미다. 상대에게 알려줄 구체적인 접속 주소는 별도로 필요하다.
- 서버가 포트를 열어도 방화벽·라우팅·NAT 조건 때문에 외부 접속이 막힐 수 있다 → [[ip-routing]]·[[network-timeout]].

## 소켓 API가 보장하지 않는 것

읽기 한 번은 전문 한 건이 아니다 → [[tcp-message-framing]]. 쓰기 호출이 끝나도 상대 업무 완료를 뜻하지 않는다 → [[tcp]]·[[idempotency]]. 일반 TCP 소켓에서 보이지 않는 헤더는 Wireshark 같은 패킷 분석 도구로 확인할 수 있다.
