# 스레드(Thread): 기초부터 실무까지

## 1. 프로그램, 프로세스, 스레드

스레드를 이해하려면 프로그램과 프로세스부터 구분해야 한다.

### 프로그램

프로그램은 디스크에 저장된 실행 가능한 코드와 데이터의 집합이다. 아직 실행하지 않은 애플리케이션 파일은 프로그램이다.

### 프로세스

프로그램을 실행하면 운영체제가 메모리와 각종 자원을 할당한다. 이렇게 실행 중인 프로그램을 **프로세스(Process)**라고 한다.

프로세스는 일반적으로 다음 자원을 가진다.

- 코드와 데이터
- Heap 메모리
- 열린 파일
- 네트워크 연결
- 운영체제가 관리하는 각종 자원
- 하나 이상의 스레드

### 스레드

스레드는 **프로세스 안에서 명령을 실제로 실행하는 하나의 작업 흐름**이다.

```text
애플리케이션 프로세스
├── 메인 스레드
├── 요청 처리 스레드
├── 예약 작업 스레드
└── 비동기 작업 스레드
```

하나의 프로세스 안에는 여러 스레드가 존재할 수 있다. 각 스레드는 서로 다른 코드를 진행할 수 있지만, 같은 프로세스의 메모리와 자원을 상당 부분 공유한다.

---

## 2. 단일 스레드와 멀티 스레드

### 단일 스레드

스레드 하나가 모든 작업을 순서대로 실행한다.

```text
작업 A 시작 → 작업 A 종료
                         → 작업 B 시작 → 작업 B 종료
```

```java
public static void main(String[] args) {
    doWorkA();
    doWorkB();
}
```

`doWorkA()`가 끝나기 전에는 `doWorkB()`가 시작되지 않는다.

### 멀티 스레드

여러 스레드가 작업을 나누어 진행한다.

```text
스레드 1: 작업 A ─────────────
스레드 2:     작업 B ─────────
스레드 3:         작업 C ─────
```

작업을 겹쳐 진행할 수 있지만, 공유 데이터에 동시에 접근하면 예상하지 못한 결과가 생길 수 있다.

---

## 3. 동시성과 병렬성

### 동시성(Concurrency)

여러 작업이 같은 시간 구간 안에서 함께 진전되는 성질이다. CPU 코어가 하나라면 운영체제가 작업을 빠르게 번갈아 실행할 수 있다.

```text
시간 →
작업 A: 실행 ── 대기 ── 실행
작업 B: 대기 ── 실행 ── 대기
```

### 병렬성(Parallelism)

여러 CPU 코어가 여러 작업을 실제 같은 순간에 실행하는 것이다.

```text
CPU Core 1 → 작업 A
CPU Core 2 → 작업 B
```

| 개념 | 의미 |
|---|---|
| 동시성 | 여러 작업이 번갈아 실행되며 함께 진행됨 |
| 병렬성 | 여러 작업이 실제 같은 순간에 실행됨 |

멀티 스레딩은 동시성을 구현하는 한 방법이며, 실행 환경에 여러 CPU 코어가 있으면 병렬 실행도 가능하다.

---

## 4. 스케줄링과 문맥 교환

운영체제의 **스케줄러**는 실행 가능한 스레드 중 어떤 스레드에 CPU 시간을 줄지 결정한다.

실행 중인 스레드를 다른 스레드로 바꾸는 것을 **문맥 교환(Context Switching)**이라고 한다. 이때 운영체제는 현재 실행 위치, 레지스터 값, Stack 포인터 같은 실행 정보를 저장하고 다음 스레드의 정보를 복원한다.

문맥 교환에는 비용이 든다. 따라서 스레드가 많다고 항상 처리 속도가 빨라지는 것은 아니다.

```text
적절한 스레드 수
→ 자원 대기 시간 활용
→ 처리량 향상

지나치게 많은 스레드
→ 문맥 교환 증가
→ 메모리 사용 증가
→ 처리 속도 저하
```

## 5. 스레드가 공유하는 것과 독립적으로 가지는 것

같은 프로세스의 스레드들은 다음 자원을 공유한다.

- Heap 영역의 객체
- `static` 변수
- 프로세스의 코드
- 파일과 네트워크 연결
- 기타 프로세스 자원

각 스레드는 다음 정보를 독립적으로 가진다.

- Stack
- 현재 실행 위치
- 메서드 호출 정보
- 지역 변수

```text
프로세스
│
├── Heap: 모든 스레드가 공유
│   ├── 객체 A
│   └── 객체 B
│
├── Thread 1 Stack
│   └── 지역 변수와 호출 정보
│
└── Thread 2 Stack
    └── 지역 변수와 호출 정보
```

공유 객체는 여러 스레드가 동시에 읽거나 변경할 수 있기 때문에 동시성 제어가 필요할 수 있다.

## 6. Java에서 스레드 생성하기

### `Thread` 클래스 상속

```java
public class WorkerThread extends Thread {

    @Override
    public void run() {
        System.out.println("새 스레드에서 실행");
    }
}
```

```java
WorkerThread worker = new WorkerThread();
worker.start();
```

### `Runnable` 구현

```java
public class WorkerTask implements Runnable {

    @Override
    public void run() {
        System.out.println("작업 실행");
    }
}
```

```java
Runnable task = new WorkerTask();
Thread worker = new Thread(task);
worker.start();
```

람다식으로도 작성할 수 있다.

```java
Thread worker = new Thread(() -> {
    System.out.println("작업 실행");
});

worker.start();
```

`Runnable`은 실행할 작업과 그것을 실행하는 스레드를 분리한다.

## 7. `start()`와 `run()`의 차이

### `start()`

```java
worker.start();
```

JVM에 새 스레드 생성을 요청한다. 준비가 완료되면 새 스레드에서 `run()`이 호출된다.

### `run()`

```java
worker.run();
```

새 스레드를 만들지 않는다. 현재 스레드가 일반 메서드처럼 `run()`을 실행한다.

```java
public class ThreadNameExample extends Thread {

    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName());
    }

    public static void main(String[] args) {
        ThreadNameExample first = new ThreadNameExample();
        ThreadNameExample second = new ThreadNameExample();

        first.start(); // 새 스레드
        second.run();  // main 스레드
    }
}
```

비동기적으로 새 실행 흐름을 시작하려면 `run()`이 아니라 `start()`를 호출해야 한다.

---

## 8. 스레드의 생명주기

Java의 스레드는 다음 상태를 거칠 수 있다.

```text
NEW
  ↓ start()
RUNNABLE
  ↓
BLOCKED / WAITING / TIMED_WAITING
  ↓
RUNNABLE
  ↓
TERMINATED
```

| 상태 | 의미 |
|---|---|
| `NEW` | 객체는 생성됐지만 아직 시작되지 않음 |
| `RUNNABLE` | 실행 가능하거나 CPU에서 실행 중 |
| `BLOCKED` | 다른 스레드가 가진 모니터 락을 기다림 |
| `WAITING` | 다른 동작이 일어날 때까지 기한 없이 기다림 |
| `TIMED_WAITING` | 정해진 시간 동안 기다림 |
| `TERMINATED` | `run()` 실행이 종료됨 |

한 번 종료된 `Thread` 객체를 다시 시작할 수는 없다.

## 9. `sleep()`과 `join()`

### `sleep()`

`Thread.sleep()`은 **현재 실행 중인 스레드**를 일정 시간 대기시킨다.

```java
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
}
```

대기 중인 스레드는 CPU를 계속 점유하지 않는다. 다만 `sleep()`은 현재 보유한 모니터 락을 자동으로 반환하지 않는다.

### `join()`

`join()`은 대상 스레드가 끝날 때까지 현재 스레드를 기다리게 한다.

```java
Thread worker = new Thread(() -> doWork());

worker.start();
worker.join();

System.out.println("worker 종료 후 실행");
```

`join()`을 사용하면 실행 순서를 맞출 수 있지만, 기다리는 스레드는 그동안 다른 작업을 진행하지 못한다.

---

## 10. 인터럽트

인터럽트는 실행 중인 스레드에 **중단 요청이 들어왔다는 신호**를 전달하는 협력적 취소 방식이다.

```java
worker.interrupt();
```

인터럽트는 스레드를 강제로 종료하지 않는다. 대상 코드가 인터럽트 상태를 확인하고 안전하게 종료해야 한다.

```java
while (!Thread.currentThread().isInterrupted()) {
    doUnitOfWork();
}
```

대기 중 `InterruptedException`을 받았다면, 예외를 처리한 후 상위 코드도 신호를 알 수 있도록 인터럽트 상태를 복구하는 경우가 많다.

```java
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
    return;
}
```

## 11. 스레드 풀

요청이나 작업마다 새 스레드를 만들면 스레드 수가 제한 없이 증가할 수 있다. **스레드 풀(Thread Pool)**은 일정 수의 스레드를 만들어 재사용한다.

```text
작업 대기열
├── 작업 1
├── 작업 2
├── 작업 3
└── 작업 4

스레드 풀
├── Worker A
├── Worker B
└── Worker C
```

주요 장점은 다음과 같다.

- 생성되는 스레드 수를 제한한다.
- 스레드 생성과 제거 비용을 줄인다.
- 처리량을 조절할 수 있다.
- 작업을 대기열에 보관할 수 있다.
- 종료와 모니터링을 중앙에서 관리할 수 있다.

Java에서는 `ExecutorService`를 사용할 수 있다.

```java
ExecutorService executor =
        Executors.newFixedThreadPool(10);

executor.submit(() -> doWork());

executor.shutdown();
```

실무에서는 스레드 수뿐 아니라 다음 설정도 함께 고려해야 한다.

- 핵심 스레드 수
- 최대 스레드 수
- 작업 대기열 크기
- 대기열이 가득 찼을 때의 거부 정책
- 종료 시 대기 작업 처리 방법
- 작업별 제한 시간

무제한 대기열은 메모리 문제를 일으킬 수 있고, 지나치게 작은 대기열은 작업 거부를 빈번하게 만들 수 있다.

## 12. 비동기와 멀티 스레딩

두 개념은 관련 있지만 동일하지 않다.

### 비동기(Asynchronous)

작업 완료를 기다리지 않고 다음 흐름을 진행하는 실행 방식이다.

```text
작업 요청
→ 완료를 기다리지 않고 다음 작업 진행
→ 나중에 결과 처리
```

### 멀티 스레딩

프로세스가 여러 스레드를 사용하는 구현 방식이다.

별도 스레드로 비동기를 구현할 수 있지만, 이벤트 루프나 비동기 I/O처럼 적은 스레드로도 비동기 처리를 구현할 수 있다.

---

## 13. CPU 중심 작업과 I/O 중심 작업

### CPU 중심 작업

CPU를 지속적으로 사용하는 계산 작업이다.

- 대규모 수치 계산
- 영상 처리
- 압축과 암호 연산

스레드 수를 CPU 코어 수보다 크게 늘려도 성능 향상이 제한적일 수 있다.

### I/O 중심 작업

외부 자원의 응답을 기다리는 시간이 많은 작업이다.

- DB 조회
- 네트워크 통신
- 파일 읽기와 쓰기

I/O 대기 중에는 다른 스레드가 CPU를 사용할 수 있으므로 CPU 코어 수보다 많은 스레드가 유용할 수 있다. 그러나 DB 연결 수, 외부 서비스의 처리 한도, 메모리 등의 제약도 함께 고려해야 한다.

---

## 14. 경쟁 상태(Race Condition)

여러 스레드가 공유 데이터를 동시에 변경할 때, 실행 순서에 따라 결과가 달라지는 문제를 **경쟁 상태**라고 한다.

```java
private int count = 0;

public void increment() {
    count++;
}
```

`count++`는 개념적으로 다음 단계로 구성된다.

```text
1. 현재 값 읽기
2. 1 더하기
3. 결과 저장
```

두 스레드가 동시에 0을 읽고 각각 1을 저장하면, 두 번 증가했는데도 최종 값은 1이 될 수 있다.

## 15. 원자성, 가시성, 순서성

멀티 스레드 문제는 주로 세 관점으로 이해한다.

### 원자성(Atomicity)

하나의 작업이 중간 상태 없이 전부 실행되거나 전혀 실행되지 않는 성질이다. `count++` 같은 복합 연산은 원자적이지 않다.

### 가시성(Visibility)

한 스레드가 변경한 값을 다른 스레드가 적절한 시점에 볼 수 있는 성질이다.

### 순서성(Ordering)

프로그램에 작성된 연산 순서와 다른 스레드가 관찰하는 순서가 일관되는 성질이다. 컴파일러와 CPU는 결과가 같다고 판단되는 범위에서 명령을 재배치할 수 있으므로 동기화가 필요할 수 있다.

---

## 16. `synchronized`, `volatile`, 원자 클래스

### `synchronized`

한 번에 한 스레드만 특정 임계 구역을 실행하게 한다.

```java
public synchronized void increment() {
    count++;
}
```

상호 배제와 함께 락 경계에서 가시성도 제공한다.

### `volatile`

변수의 최신 값을 스레드 사이에 보이도록 하는 데 사용한다.

```java
private volatile boolean running = true;
```

하지만 복합 연산을 원자적으로 만들지는 않는다.

```java
private volatile int count = 0;

count++; // 여전히 원자적이지 않음
```

### 원자 클래스

`AtomicInteger` 같은 클래스는 증가, 교환, 비교 후 갱신 등의 원자 연산을 제공한다.

```java
AtomicInteger count = new AtomicInteger();
count.incrementAndGet();
```

| 도구 | 주된 용도 |
|---|---|
| `synchronized` | 임계 구역의 상호 배제와 가시성 |
| `volatile` | 단일 변수의 가시성과 일부 순서 보장 |
| 원자 클래스 | 락 없이 사용할 수 있는 원자 연산 |
| 명시적 Lock | 타임아웃, 조건 변수 등 세밀한 락 제어 |

---

## 17. 데드락과 기아

### 데드락(Deadlock)

두 개 이상의 스레드가 서로 상대방이 가진 자원을 기다리며 영원히 진행하지 못하는 상태다.

```text
Thread A: Lock 1 보유 → Lock 2 대기
Thread B: Lock 2 보유 → Lock 1 대기
```

예방 방법에는 일관된 락 획득 순서, 불필요한 중첩 락 제거, 타임아웃이 있는 락 사용 등이 있다.

### 기아(Starvation)

특정 스레드가 계속 실행 기회를 얻지 못하는 상태다. 불공정한 락 경쟁이나 특정 작업의 자원 독점 때문에 발생할 수 있다.

---

## 18. 스레드 안전성

여러 스레드가 동시에 접근해도 올바르게 동작하는 성질을 **스레드 안전성(Thread Safety)**이라고 한다.

메서드의 지역 변수는 일반적으로 각 스레드의 Stack에 존재하므로 독립적이다.

```java
public int calculate(int value) {
    int result = value * 2;
    return result;
}
```

반면 공유 객체의 변경 가능한 필드는 주의해야 한다.

```java
public class Processor {
    private String currentValue;

    public void process(String value) {
        currentValue = value;
        use(currentValue);
    }
}
```

여러 스레드가 `process()`를 호출하면 `currentValue`를 서로 덮어쓸 수 있다. 가능한 경우 상태를 지역 변수로 한정하고, 공유되는 변경 가능 상태를 최소화하는 것이 좋다.

불변 객체도 스레드 안전한 설계에 유용하다.

## 19. 비동기 작업의 예외와 결과

새 스레드에서 발생한 예외는 그 스레드를 시작한 원래 호출자에게 자동으로 전달되지 않는다.

```java
new Thread(() -> {
    throw new RuntimeException("작업 실패");
}).start();
```

따라서 비동기 작업은 다음을 명시적으로 다뤄야 한다.

- 오류 기록
- 실패 상태 관리
- 재시도 여부
- 작업 시간 제한
- 취소
- 호출자에게 결과 전달

`ExecutorService.submit()`이 반환하는 `Future`로 결과나 예외를 받을 수 있다.

```java
Future<String> future =
        executor.submit(() -> performTask());

String result = future.get();
```

`get()`은 결과가 준비될 때까지 현재 스레드를 기다리게 할 수 있다. 조합 가능한 비동기 흐름에는 `CompletableFuture`도 사용할 수 있다.

## 20. 트랜잭션과 스레드

많은 애플리케이션 프레임워크에서 트랜잭션 문맥은 현재 스레드에 연결된다. 따라서 새 스레드를 만들었다고 해서 기존 트랜잭션이 자동으로 이어지지는 않는다.

```text
호출 스레드
└── Transaction A

새 작업 스레드
└── Transaction A를 자동 상속하지 않음
```

새 스레드가 시작될 때 원래 트랜잭션이 아직 커밋되지 않았다면, 새 스레드는 방금 저장한 데이터를 조회하지 못할 수도 있다.

안전한 설계 방법은 다음과 같다.

- 트랜잭션 커밋 후 작업을 실행한다.
- 작업 큐나 메시지 브로커에 전달한다.
- 같은 DB 트랜잭션에서 영속적인 작업 레코드를 만든다.
- 비동기 작업이 자체 트랜잭션 경계를 가지도록 한다.

## 21. 프로세스 내부 락과 분산 환경

`synchronized`나 JVM의 Lock은 같은 프로세스 안의 스레드만 조정한다.

```text
애플리케이션 인스턴스 A의 락
애플리케이션 인스턴스 B의 락
```

여러 인스턴스가 같은 DB 데이터를 변경한다면 각 인스턴스의 메모리 락만으로는 충분하지 않다. 이때는 다음 방법을 고려할 수 있다.

- DB의 낙관적 락
- DB의 비관적 락
- 조건부 `UPDATE`
- 분산 락
- 메시지 파티셔닝과 순서 보장

---

## 22. 실무 설계 원칙

1. 작업마다 직접 스레드를 생성하지 말고 관리되는 실행기를 사용한다.
2. 스레드 수와 대기열 크기에 명시적인 상한을 둔다.
3. 공유되는 변경 가능 상태를 최소화한다.
4. 비동기 작업의 실패, 제한 시간, 취소, 재시도 정책을 정의한다.
5. 트랜잭션 문맥이 스레드 사이에 자동 전파된다고 가정하지 않는다.
6. 프로세스가 종료되어도 반드시 살아남아야 하는 작업은 메모리 스레드에만 맡기지 않는다.
7. 스레드뿐 아니라 DB 연결, 메모리, 외부 자원의 처리 한도를 함께 조정한다.
8. 로그에 작업 ID와 스레드 이름을 남겨 추적 가능성을 높인다.

## 핵심 정리

스레드는 **프로세스 안에서 코드를 실행하는 하나의 작업 흐름**이다.

멀티 스레딩은 여러 작업을 동시에 진전시키고 자원 대기 시간을 활용할 수 있게 하지만, 다음 문제를 함께 가져온다.

- 공유 데이터의 경쟁 상태
- 가시성과 원자성 문제
- 데드락
- 과도한 스레드 생성
- 비동기 예외와 작업 유실
- 트랜잭션 문맥 분리

따라서 실무에서는 단순히 스레드를 많이 만드는 것보다 **제한된 스레드 풀, 명확한 동시성 제어, 실패 관리, 영속적인 작업 전달 방식**을 함께 설계하는 것이 중요하다.
